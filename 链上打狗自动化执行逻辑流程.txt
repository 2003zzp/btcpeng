链上打狗自动化执行逻辑流程

对应脚本：
onchain_dog_bot.py

默认模式：
paper 纸交易模式，不会真实下单。

一、启动流程

1. 读取 .env
   - 加载 Telegram 通知配置。
   - 加载 webhook 交易执行端配置。
   - 不读取、不保存钱包私钥。

2. 读取配置文件
   - 默认配置文件为 onchain_dog_config.json。
   - 如果没有正式配置，可以从 onchain_dog_config.example.json 复制一份。
   - 支持运行时用 --mode paper 或 --mode webhook 覆盖执行模式。

3. 读取运行状态
   - 状态文件路径为 data/onchain_dog_state.json。
   - 记录纸交易余额、当日盈亏、连续亏损次数、已开仓池子、当前持仓和历史平仓记录。
   - 如果日期变化，会自动重置当日交易统计。


二、扫描新池子

1. 按配置里的 networks 扫描链
   默认扫描：
   - bsc
   - base
   - solana

2. 从 GeckoTerminal 拉取新池子
   接口逻辑：
   - /networks/{network}/new_pools
   - 每条链最多读取 new_pools_per_network 个新池。
   - 尽量同时读取 base_token 和 quote_token 信息。

3. 解析池子数据
   每个候选池会提取：
   - 链名称
   - 池子地址
   - base token 地址
   - token 名称和符号
   - quote token 符号
   - 当前美元价格
   - 池子流动性
   - 5 分钟成交额
   - 1 小时成交额
   - 24 小时成交额
   - 5 分钟买入笔数
   - 5 分钟卖出笔数
   - 5 分钟买卖比
   - 5 分钟涨幅
   - 1 小时涨幅
   - FDV 或市值
   - 池子创建时间
   - 池龄


三、硬过滤

候选池必须先通过硬过滤，否则分数直接归零，不允许开仓。

过滤条件包括：

1. 黑名单过滤
   - token 地址在 blocked_tokens 里，拒绝。
   - pool 地址在 blocked_pools 里，拒绝。

2. 基础数据过滤
   - 没有 token 地址，拒绝。
   - 没有价格，拒绝。
   - quote token 不在 allowed_quote_symbols 里，拒绝。

3. 池龄过滤
   - 池子太新，拒绝。
   - 池子太老，拒绝。
   - 默认要求池龄至少 120 秒，最多 7200 秒。

4. 流动性过滤
   - 流动性低于 min_liquidity_usd，拒绝。
   - 默认最低 20000 美元。

5. 成交额过滤
   - 1 小时成交额低于 min_volume_h1_usd，拒绝。
   - 24 小时成交额低于 min_volume_h24_usd，拒绝。

6. 交易笔数过滤
   - 5 分钟交易笔数低于 min_txns_m5，拒绝。

7. 买卖比过滤
   - 买入卖出比太低，说明买盘不够，拒绝。
   - 买入卖出比太高，说明买盘过于单边，也拒绝。

8. 短线涨幅过滤
   - 5 分钟涨幅超过 max_price_change_m5_pct，拒绝。
   - 目的是避免刚被暴拉后追高。

9. FDV / 流动性过滤
   - 如果 FDV 或市值相对流动性过高，拒绝。
   - 默认 max_fdv_liquidity_ratio 为 80。


四、信号打分

通过硬过滤后，脚本会给候选池打 0 到 100 分。

基础分：
通过全部硬过滤后，先给 30 分。

加分项：

1. 流动性加分
   - 流动性越高，分数越高。
   - 最多加 15 分。

2. 1 小时成交额加分
   - 成交越活跃，分数越高。
   - 最多加 15 分。

3. 5 分钟交易笔数加分
   - 短线交易越活跃，分数越高。
   - 最多加 10 分。

4. 买卖比加分
   - 买卖比处在配置范围内，加 10 分。

5. 1 小时涨幅加分
   - 1 小时涨幅为正时加分。
   - 但不是无限加分，避免只追暴涨。

6. quote token 加分
   - quote token 在允许列表中，加 5 分。

7. FDV / 流动性结构加分
   - 有 FDV 或市值数据，且流动性结构可计算，加 5 分。

8. 新池加分
   - 池龄在 30 分钟以内，加 5 分。

开仓阈值：
默认 min_score_to_buy 为 75 分。
低于该分数，不开仓。


五、开仓前风控

即使候选池分数达标，也必须通过全局风控。

风控条件包括：

1. 最大持仓数
   - 当前持仓数达到 max_open_positions，不开新仓。

2. 每日最大交易次数
   - 当日交易次数达到 max_trades_per_day，不开新仓。

3. 每日最大亏损金额
   - 当日已实现亏损达到 max_daily_loss_usd，不开新仓。

4. 每日最大亏损比例
   - 当日已实现亏损达到 max_daily_loss_pct，不开新仓。

5. 连续亏损次数
   - 连续亏损达到 max_consecutive_losses，不开新仓。

6. 亏损后冷却期
   - 最近一笔亏损后，如果仍在 cooldown_after_loss_sec 内，不开新仓。

7. 纸交易余额检查
   - paper 模式下，余额不足 fixed_trade_usd，不开新仓。

8. webhook 检查
   - webhook 模式下，如果没有配置 ONCHAIN_TRADE_WEBHOOK_URL，不开新仓。


六、固定仓位开仓

1. 开仓金额固定
   - 使用 execution.fixed_trade_usd。
   - 默认每笔 25 美元。

2. paper 模式
   - 不真实下单。
   - 用当前池子价格模拟买入。
   - 从纸交易余额里扣除 fixed_trade_usd。

3. webhook 模式
   - 向配置的 webhook 地址发送买入请求。
   - 请求内容包括链、池子地址、token 地址、token 符号、买入金额、分数和入场理由。
   - webhook 返回 accepted、filled 或 ok 才视为成功。

4. 记录持仓
   成功开仓后记录：
   - 入场时间
   - 入场价格
   - 入场流动性
   - 买入金额
   - 模拟 token 数量
   - 当前剩余数量
   - 最高价
   - 最高价时间
   - 止盈目标命中记录
   - 入场分数和理由

5. 防止重复买入
   - 成功开仓后，将该池子写入 seen_pools。
   - 同一个池子后续不会重复开仓。


七、持仓管理

每轮扫描开始时，脚本会先管理已有持仓，再寻找新机会。

持仓管理流程：

1. 根据持仓里的 network 和 pool_address 重新读取池子数据。
2. 更新当前价格。
3. 如果当前价格高于历史最高价，更新最高价和最高价时间。
4. 依次检查退出条件。


八、自动退出逻辑

退出逻辑按优先级执行，一轮只触发一个退出动作。

1. 固定止损
   - 如果当前亏损达到 stop_loss_pct，全部卖出。
   - 默认止损为 -25%。

2. 流动性塌陷退出
   - 如果当前流动性低于入场流动性的一定比例，全部卖出。
   - 默认 liquidity_exit_ratio 为 0.45。

3. 分批止盈
   默认规则：
   - 涨 80%，卖 40%。
   - 涨 150%，卖 30%。
   - 涨 300%，卖 20%。
   - 每个止盈目标只执行一次。

4. 移动止盈
   - 当收益达到 trailing_start_gain_pct 后启动。
   - 如果从最高价回撤达到 trailing_drawdown_pct，全部卖出。
   - 默认涨 120% 后启动，回撤 35% 退出。

5. 最大持仓时间退出
   - 持仓超过 max_hold_minutes，全部卖出。
   - 默认 60 分钟。

6. 无新高退出
   - 持仓盈利时，如果 no_new_high_exit_minutes 内没有刷新高，全部卖出。
   - 默认 20 分钟。


九、卖出和平仓记录

1. paper 模式
   - 用当前价格模拟卖出。
   - 卖出所得加入纸交易余额。
   - 计算已实现盈亏。

2. webhook 模式
   - 向 webhook 发送 sell 请求。
   - 请求内容包括链、池子地址、token 地址、卖出比例、数量、预期价格和退出原因。

3. 更新状态
   - 更新剩余数量。
   - 写入本次退出记录。
   - 更新总已实现盈亏。
   - 更新当日已实现盈亏。
   - 如果亏损，连续亏损次数加 1，并记录最近亏损时间。
   - 如果完整平仓且盈利，连续亏损次数归零。

4. 完整平仓
   - 如果剩余数量接近 0，将持仓移入 closed_positions。
   - 从当前 positions 中删除。


十、日志和通知

1. 控制台日志
   - 显示候选池、过滤原因、分数、买入、卖出和错误。

2. 事件日志
   - 写入 data/onchain_dog_events.jsonl。
   - 每行是一条 JSON 事件。

3. 状态文件
   - 写入 data/onchain_dog_state.json。
   - 程序重启后会继续管理已有纸交易或 webhook 状态。

4. Telegram 通知
   如果 .env 配置了 TELEGRAM_BOT_TOKEN 和 TELEGRAM_CHAT_ID：
   - 买入时通知。
   - 卖出时通知。
   - 通知内容包括 token、链、价格、金额、分数和盈亏。


十一、运行方式

初始化配置：

copy .\onchain_dog_config.example.json .\onchain_dog_config.json

单轮扫描：

python .\onchain_dog_bot.py --once

持续运行：

python .\onchain_dog_bot.py

强制纸交易模式：

python .\onchain_dog_bot.py --mode paper

强制 webhook 模式：

python .\onchain_dog_bot.py --mode webhook


十二、真实交易接入方式

脚本本身不直接签名、不保存私钥。

真实交易需要外部 webhook 执行器：

1. 在 .env 中配置：
   ONCHAIN_TRADE_WEBHOOK_URL=https://your-executor.example/trade
   ONCHAIN_TRADE_WEBHOOK_SECRET=optional_shared_secret

2. 在配置中设置：
   execution.mode = webhook

3. 外部执行器需要自己处理：
   - 钱包签名
   - 路由选择
   - 滑点控制
   - token 安全检查
   - 蜜罐检查
   - 卖出测试
   - 链上交易广播


十三、核心原则

1. 固定仓位，不临场加码。
2. 先硬过滤，再打分。
3. 先风控，再开仓。
4. 买入自动化，卖出也必须自动化。
5. 达到亏损和连续失败阈值后，宁可停机，不继续硬冲。
6. 默认纸交易，真实交易必须显式接 webhook。
7. 不做夹子、抢跑、三明治攻击，也不绕过项目方反 Bot 机制。


十四、风险说明

链上新池风险极高，脚本只能自动执行规则，不能保证盈利，也不能保证识别所有恶意合约。
真实交易前，必须先长期纸交易验证参数，并让外部交易执行器加入更严格的合约安全检查。
